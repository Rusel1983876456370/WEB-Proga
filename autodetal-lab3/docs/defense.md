# Что показывать на защите ЛР3

1. Запустите start.bat, откройте сайт и Swagger /docs.
2. Объясните архитектуру: браузер → HTTP fetch → FastAPI → SQLAlchemy → SQLite.
3. GET /api/categories возвращает категории, GET /api/parts — детали.
4. В Swagger раскройте POST /api/parts, нажмите Try it out, передайте JSON из README с новым артикулом. Покажите 201 и id.
5. GET /api/parts/{part_id}: подставьте полученный id, получите 200 и объект.
6. PATCH /api/parts/{part_id}: передайте только {"price":"849.90"}. Покажите 200 и изменённую цену; остальные поля сохранены.
7. Обновите сайт кнопкой «Обновить с сервера»: деталь и цена появляются из БД.
8. Перезагрузите браузер; остановите сервер Ctrl+C и запустите заново. Запись сохранена в data/autodetal.db.
9. Покажите таблицу через DB Browser for SQLite или командой python scripts/inspect_db.py.
10. Через форму сайта добавьте деталь с другим артикулом, измените её, перезагрузите страницу, затем удалите и подтвердите действие.
11. В Swagger удалите запись из шага 4: DELETE возвращает 204, повторный GET — 404.
12. Проверьте ошибку: повторный артикул → 400, отрицательная цена → 422, неизвестный id → 404.
13. Откройте /openapi.json. Объясните, что спецификация генерируется из маршрутов и Pydantic-схем.

## Короткие ответы

**Что изменилось по сравнению с ЛР2?** Раньше каталог сохранялся в localStorage одного браузера. Теперь записи хранятся в реляционной БД, а JS обращается к серверу через fetch.

**Основная сущность?** Запчасть Part. Связанная сущность Category. В одной категории много запчастей; связь через category_id.

**CRUD?** Create — POST; Read — GET; Update — PATCH; Delete — DELETE.

**Почему PATCH?** Можно передать только изменившиеся поля. PUT используется для полной замены ресурса; в работе он не нужен.

**Где проверяются данные?** HTML/JS помогают пользователю заполнить форму, но окончательная проверка выполняется Pydantic на сервере. БД отдельно обеспечивает NOT NULL, UNIQUE, CHECK и FOREIGN KEY.

**Что означает 201?** Создана новая запись; в теле возвращается объект, в Location — его API-адрес.

**Почему 204 без JSON?** Удаление успешно; возвращать тело ответа при 204 нельзя.

**Зачем SQLAlchemy?** Модели Python соответствуют таблицам. Сессия выполняет SELECT/INSERT/UPDATE/DELETE и управляет транзакцией.

**Что такое rollback?** Откат неудачной транзакции; после конфликта уникальности соединение снова пригодно для следующих запросов.

**Зачем внешний ключ?** Нельзя создать деталь с категорией, которой нет, или удалить используемую категорию.

**Почему SQLite?** Методичка допускает её для локальной разработки; не нужен отдельный сервер. БД физически хранится в файле.

**Как доказать, что данные не в массиве JS?** Открыть Network → Fetch/XHR, показать HTTP-запросы, SELECT в SQLite и сохранение после нового процесса backend.

**JS state тоже хранит массив?** Да, это временная копия ответа API для отображения. Источник постоянных данных — БД; localStorage каталогом не используется.

**Что такое OpenAPI и Swagger?** OpenAPI — машиночитаемое описание контракта API. Swagger UI отображает его и позволяет отправлять запросы.

**Что ещё нужно для сдачи?** Загрузить подготовленный Git-репозиторий в свой GitHub/GitLab и приложить реальную ссылку. Скриншоты и README уже находятся в проекте.
