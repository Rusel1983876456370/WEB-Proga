## 1. Цель работы

Цель лабораторной работы — развернуть веб-приложение «АвтоДеталь — каталог автозапчастей» в Docker и организовать мониторинг его контейнера с помощью cAdvisor, Prometheus и Grafana.

В ходе работы подготовлены Docker-образ приложения, конфигурация совместного запуска четырёх сервисов, сбор контейнерных метрик, хранение временных рядов и дашборд для отображения процессорной нагрузки, памяти, сетевой активности и доступных дисковых показателей.

---

## 2. Постановка задачи

В качестве основы используется проект **«АвтоДеталь — каталог автозапчастей»**, разработанный в лабораторной работе №3. Приложение содержит frontend на HTML, CSS и JavaScript, backend на FastAPI и базу SQLite.

В ЛР3 сервер запускался непосредственно через Python и Uvicorn. В ЛР4 необходимо перенести запуск в Docker и подключить систему наблюдения за ресурсами контейнеров.

Необходимо выполнить следующие задачи:

- создать Dockerfile для существующего приложения;
- описать сервисы `webapp`, `cadvisor`, `prometheus` и `grafana` в Docker Compose;
- подключить сервисы к общей Docker-сети;
- настроить cAdvisor для получения метрик контейнеров;
- настроить периодический опрос cAdvisor системой Prometheus;
- подключить Prometheus как источник данных Grafana;
- создать дашборд CPU, памяти, сети и дискового ввода-вывода;
- проверить доступность сервисов и поступление метрик приложения;
- обеспечить сохранение БД и истории мониторинга;
- подготовить инструкции запуска и проверки.

Согласно последнему уточнению к заданию блок создания искусственной нагрузки исключён. Мониторинг выполняется при обычной работе приложения.

## 5. Архитектура системы мониторинга

В проекте используются четыре сервиса:

| Сервис | Назначение |
|---|---|
| `webapp` | Обслуживает каталог, REST API и операции с SQLite |
| `cadvisor` | Читает показатели контейнеров и публикует `/metrics` |
| `prometheus` | Опрашивает cAdvisor и сохраняет временные ряды |
| `grafana` | Выполняет запросы к Prometheus и отображает результаты |

Последовательность получения данных:

1. Контейнер приложения потребляет процессорное время, память и сетевые ресурсы.
2. cAdvisor получает показатели через интерфейсы Linux-хоста Docker и сведения о контейнерах.
3. Prometheus каждые 15 секунд обращается к `http://cadvisor:8080/metrics`.
4. Полученные значения сохраняются с временными метками и наборами меток контейнера.
5. Grafana обращается к `http://prometheus:9090` и выполняет PromQL-запросы.
6. Результаты отображаются на панелях дашборда.

При использовании Docker Desktop на Windows наблюдаются контейнеры Linux-среды Docker. Показатели не описывают все процессы операционной системы Windows.

## 6. Создание Docker-образа приложения

Для приложения подготовлен Dockerfile на базе `python:3.12-slim`.

Основной фрагмент:

```dockerfile
FROM python:3.12-slim
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1
WORKDIR /app
COPY backend/requirements.txt /app/backend/requirements.txt
RUN pip install --no-cache-dir -r backend/requirements.txt
COPY backend /app/backend
COPY frontend /app/frontend
COPY data/autodetal.db /app/seed-data/autodetal.db
COPY scripts/container_start.py /app/scripts/container_start.py
```

Сначала копируется список зависимостей и выполняется их установка. Затем добавляются исходники сервера, frontend и начальная база. Такой порядок позволяет повторно использовать слой зависимостей, если изменён только код приложения.

Создаётся пользователь `app` с UID 10001. Каталог `/app/data` передаётся этому пользователю, после чего сервер запускается без прав root.

Файл `.dockerignore` исключает из контекста сборки виртуальное окружение, кэш Python, тесты, документацию, архивы и `.env`.

## 7. Запуск приложения и первичная подготовка базы данных

Контейнер запускает `scripts/container_start.py`. При первом старте скрипт копирует исходную БД в рабочий каталог, если её ещё нет:

```python
target = Path('/app/data/autodetal.db')
if not target.exists():
    shutil.copy2('/app/seed-data/autodetal.db', target)
```

После подготовки файла выполняется запуск Uvicorn:

```python
os.execvp('python', [
    'python', '-m', 'uvicorn', 'backend.app.main:app',
    '--host', '0.0.0.0', '--port', '8000'
])
```

Адрес `0.0.0.0` позволяет принимать обращения через сетевой интерфейс контейнера. Для доступа с компьютера порт публикуется через Docker Compose.

Строка подключения внутри контейнера:

```text
sqlite:////app/data/autodetal.db
```

Рабочая БД находится в томе `app_data`. При следующих запусках файл уже существует и не заменяется исходной копией. Таким образом, добавленные и изменённые записи не перезаписываются скриптом инициализации.

## 8. Настройка Docker Compose

Файл `docker-compose.yml` описывает проект `autodetal-lab4`. Сервис приложения собирается из локального Dockerfile, а компоненты мониторинга используют готовые образы.

| Сервис | Образ |
|---|---|
| `webapp` | `autodetal-lab4-webapp:local`, локальная сборка |
| `cadvisor` | `ghcr.io/google/cadvisor:0.55.1` |
| `prometheus` | `prom/prometheus:v3.5.0` |
| `grafana` | `grafana/grafana:12.3.2` |

Фрагмент сервиса приложения:

```yaml
webapp:
  build: .
  image: autodetal-lab4-webapp:local
  restart: unless-stopped
  ports:
    - "127.0.0.1:8000:8000"
  environment:
    DATABASE_URL: sqlite:////app/data/autodetal.db
  volumes:
    - app_data:/app/data
  cpus: 1.0
  mem_limit: 512m
  networks: [monitoring]
```

Параметры `cpus` и `mem_limit` задают ограничения ресурсов приложения. Политика `unless-stopped` предусматривает автоматический перезапуск контейнера, кроме случаев его явной остановки.

`depends_on` задаёт порядок запуска компонентов. Готовность сервисов дополнительно проверяется отдельным сценарием, поскольку запуск контейнера не означает немедленную готовность его HTTP-интерфейса.

## 9. Сеть и доступ к сервисам

Все сервисы подключены к сети `monitoring` с драйвером `bridge`. Внутри сети контейнеры обращаются друг к другу по именам сервисов.

| Обращение | Внутренний адрес |
|---|---|
| Prometheus к cAdvisor | `http://cadvisor:8080/metrics` |
| Grafana к Prometheus | `http://prometheus:9090` |
| Проверка Grafana из webapp | `http://grafana:3000/api/health` |

Для браузера на компьютере используются опубликованные порты:

| Страница | Адрес |
|---|---|
| Каталог «АвтоДеталь» | `http://localhost:8000` |
| Swagger UI | `http://localhost:8000/docs` |
| cAdvisor | `http://localhost:8080` |
| Метрики cAdvisor | `http://localhost:8080/metrics` |
| Prometheus | `http://localhost:9090` |
| Цели Prometheus | `http://localhost:9090/targets` |
| Grafana | `http://localhost:3000` |
| Дашборд проекта | `http://localhost:3000/d/autodetal-lab4` |

Внутри контейнера `localhost` обозначает сам этот контейнер. Поэтому для источника Grafana используется имя `prometheus`, а не `localhost`.

Публикация портов привязана к `127.0.0.1`, поэтому веб-интерфейсы предназначены для доступа с локального компьютера.

## 10. Настройка cAdvisor

cAdvisor используется для получения показателей CPU, памяти, сети и дискового ввода-вывода контейнеров.

В Compose включены привилегированный режим и доступ к пространствам PID и cgroup хоста Docker:

```yaml
privileged: true
pid: host
cgroup: host
command:
  - --docker_only=true
  - --housekeeping_interval=10s
  - --store_container_labels=true
```

Для чтения системных сведений подключаются каталоги:

| Путь хоста | Путь контейнера | Назначение |
|---|---|---|
| `/` | `/rootfs` | Доступ к файловой системе хоста Docker |
| `/var/run` | `/var/run` | Сведения и интерфейсы работающих сервисов, включая Docker socket |
| `/sys` | `/sys` | Системная информация, включая cgroups |
| `/var/lib/docker` | `/var/lib/docker` | Данные стандартного каталога Docker |
| `/dev/disk` | `/dev/disk` | Сведения о дисковых устройствах при их наличии |

Монтирования заданы с флагом `ro`. Привилегированный режим используется сборщиком для доступа к системным данным; само приложение работает от отдельного пользователя.

Параметр `--store_container_labels=true` сохраняет метки контейнеров. В дальнейшем они позволяют выделять приложение среди остальных сервисов.

## 11. Конфигурация Prometheus

Prometheus использует pull-модель: самостоятельно обращается к источнику метрик через заданный интервал.

Основная конфигурация:

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 15s
scrape_configs:
  - job_name: cadvisor
    static_configs:
      - targets: [cadvisor:8080]
    metric_relabel_configs:
      - source_labels: [container_label_com_docker_compose_service]
        target_label: service
      - source_labels: [container_label_com_docker_compose_project]
        target_label: project
  - job_name: prometheus
    static_configs:
      - targets: [prometheus:9090]
```

Задание `cadvisor` получает показатели контейнеров. Задание `prometheus` собирает собственные метрики сервера Prometheus.

В `metric_relabel_configs` метки Docker Compose преобразуются в короткие имена `service` и `project`. Например, контейнер приложения выделяется сочетанием:

```promql
{job="cadvisor", project="autodetal-lab4", service="webapp"}
```

Для хранения временных рядов используется каталог `/prometheus`, подключённый к тому `prometheus_data`. Срок хранения задан параметром `--storage.tsdb.retention.time=7d`.

---

## 12. Проверка сбора метрик

Состояние целей сбора доступно на странице `/targets`. Для проверки cAdvisor применяется запрос:

```promql
up{job="cadvisor"}
```

Значение `1` означает успешный опрос cAdvisor системой Prometheus. Значение `0` указывает на ошибку опроса. Отсутствие ряда может означать отсутствие соответствующего задания или данных.

Доступность cAdvisor сама по себе не подтверждает обнаружение нужного контейнера. Поэтому отдельно проверяется память приложения:

```promql
container_memory_working_set_bytes{
  job="cadvisor",
  project="autodetal-lab4",
  service="webapp",
  image!=""
}
```

Непустой результат подтверждает наличие ряда, относящегося к `webapp`. Аналогично проверяются CPU и сеть. Проверки выполняются автоматически сценарием `scripts/check_stack.py`.

## 13. Подключение Grafana к Prometheus

Источник Prometheus настраивается автоматически через файл provisioning:

```yaml
apiVersion: 1
datasources:
  - name: Prometheus
    uid: prometheus
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    editable: true
    jsonData:
      httpMethod: POST
      timeInterval: 15s
```

UID `prometheus` используется в панелях дашборда, поэтому они обращаются к заранее определённому источнику.

Для ручной проверки подключения необходимо открыть Grafana, перейти в Connections → Data sources → Prometheus и выполнить **Save & test**.

Первоначальные учётные данные — `admin` / `admin`, если пароль не изменён через переменную окружения. После первого входа пароль можно изменить. Настройки Grafana сохраняются в томе `grafana_data`.

## 15. Расчёт процессорной нагрузки и памяти

Метрика `container_cpu_usage_seconds_total` — накопительный счётчик затраченного процессорного времени. Для определения текущей нагрузки вычисляется скорость его роста:

```promql
100 * sum(rate(container_cpu_usage_seconds_total{
  job="cadvisor",
  project="autodetal-lab4",
  service="webapp",
  image!=""
}[1m]))
```

Результат выражается в процентах одного логического ядра: 100% соответствует одному полностью занятому ядру. Это не процент загрузки всего компьютера.

Для памяти используется `container_memory_working_set_bytes`. В дашборде значения группируются по сервисам. Доля памяти приложения относительно установленного лимита вычисляется запросом:

```promql
100 *
sum(container_memory_working_set_bytes{
  job="cadvisor", project="autodetal-lab4",
  service="webapp", image!=""
})
/
sum(container_spec_memory_limit_bytes{
  job="cadvisor", project="autodetal-lab4",
  service="webapp", image!=""
})
```

Для функций `rate` требуются минимум две точки. Поэтому сразу после запуска расчёт нагрузки может ещё не отображаться. В готовом дашборде используется переменная `$__rate_interval`, согласующая окно расчёта с настройками источника и временным диапазоном.

## 16. Сетевые и дисковые показатели

Входящий сетевой трафик приложения рассчитывается по скорости роста счётчика принятых байтов:

```promql
sum(rate(container_network_receive_bytes_total{
  job="cadvisor", project="autodetal-lab4",
  service="webapp", image!="", interface!="lo"
}[1m]))
```

Для исходящего трафика используется `container_network_transmit_bytes_total`. Единица измерения — байт в секунду. Интерфейс `lo` исключается из запросов дашборда.

Дисковые панели используют `container_fs_reads_bytes_total` и `container_fs_writes_bytes_total`. Для определения скорости операций также применяется `rate`.

Доступность дисковых рядов зависит от Linux-хоста Docker, cgroups и драйвера хранения. При выполненной проверке обнаружен **один ряд `container_fs_writes_bytes_total` для webapp**. Это подтверждает наличие метрики записи, но не наличие всех возможных дисковых показателей.

Значение `0` означает измеренную нулевую скорость за рассматриваемый интервал. Отсутствующий ряд или надпись No data не равнозначны нулевому значению.

| Том | Каталог контейнера | Сохраняемые данные |
|---|---|---|
| `app_data` | `/app/data` | Рабочая SQLite-база каталога |
| `prometheus_data` | `/prometheus` | Временные ряды метрик |
| `grafana_data` | `/var/lib/grafana` | Пользователи и настройки Grafana |

Команда `docker compose down` останавливает и удаляет контейнеры проекта, сохраняя именованные тома. При следующем запуске сервисы подключают их повторно.

Параметр `-v` удаляет тома, поэтому для обычной остановки он не используется. Начальная БД в папке `data` служит источником для первого запуска, а последующая работа выполняется с файлом внутри `app_data`.

Сохранение данных обеспечено конфигурацией томов. Отдельный эксперимент с полным пересозданием контейнеров не входит в представленный протокол `check.bat`.

## 20. Запуск проекта

Для запуска на Windows используется Docker Desktop в режиме Linux containers с backend WSL2. Отдельно устанавливать Python и компоненты мониторинга на компьютер не требуется: они находятся в образах.

Порядок запуска:

1. Распаковать проект целиком.
2. Запустить Docker Desktop и дождаться готовности движка.
3. Открыть папку с `docker-compose.yml`.
4. Запустить `start.bat` или выполнить команды ниже.
5. Дождаться сборки и запуска сервисов.
6. Подождать около минуты для накопления метрик.
7. Запустить `check.bat`.
8. Открыть сайт, Prometheus и дашборд Grafana.

Команды из корня проекта:

```powershell
docker compose config -q
docker compose up -d --build
docker compose ps
```

Для просмотра логов:

```powershell
docker compose logs --tail=80
docker compose logs --tail=80 cadvisor prometheus grafana
```

Проверка конфигурации Prometheus его собственной утилитой:

```powershell
docker compose exec prometheus promtool check config /etc/prometheus/prometheus.yml
```

Последняя команда приведена как дополнительный способ диагностики; её результат не входит в предоставленный вывод `check.bat`.

Для остановки используется `stop.bat` или:

```powershell
docker compose down
```

В Linux предусмотрены `sh start.sh` и `sh check.sh`. При первом запуске нужен интернет для скачивания образов и Python-зависимостей.
